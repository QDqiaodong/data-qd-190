# 残缺牌谱分池核验 `showdown-audit`

`showdown-audit` 在单手范围内核验被遮挡录像的筹码分配。录入员对看不清的牌位只给出候选，不挑一张当真值；本命令枚举所有遵守物理牌约束的可行补全，逐池判断哪些分配已经能确认，并为仍有歧义的池给出预算内保证成功的回看决策树。它复用 v1 的牌力、贡献层、弃牌资格、并列零头与未匹配退回规则，不连接资金或游戏服务，也不读写跨手账本。

旧命令 `showdown-pots`、`showdown-ledger` 的输入、输出与错误行为不变。

## 输入

```json
{
  "hand": { "...": "v1 单手输入，牌位允许候选对象" },
  "inspectable": ["cam-7"],
  "budget": 2
}
```

`hand` 沿用 v1 单手输入的字段、类型、人数与上下限。公共牌数组与各玩家非空底牌数组中的每个位置，要么是 v1 牌字符串（如 `"6c"`），要么是：

```json
{"slot_id": "cam-7", "candidates": ["6c", "Ac"]}
```

- 全手最多 12 个候选牌位；`slot_id` 全手唯一，沿用玩家 ID 字符规则 `[A-Za-z0-9_:-]{1,64}`。
- 每个牌位 1..4 个互不重复的合法牌字符串，没有概率或先后优先级。
- 弃牌者的底牌仍可空；空数组表示没有该人的底牌证据，不创建牌位、不可回看。已给出的弃牌者牌位（固定或候选）参与全手物理牌约束。
- `inspectable` 是互不重复的 `slot_id` 列表，可为空；只有这些牌位能回看。回看一个牌位会得到真实的一张牌，不能点选其他位置，也不能假设有人确认某张候选。
- `budget` 为 0、1 或 2，是每条实际复核路径最多能回看的牌位数。可回看列表与预算不改变初始证据。

### 输入错误与正常无补全

结构、字段、金额、座位、候选列表或回看参数非法，以及仅从贡献与弃牌信息就能判定某匹配层没有有资格者，按输入错误以状态 2 退出，不写出结果。

结构合法但牌证没有任何可行补全（两处固定牌相同、多个牌位争用同一组候选等）是正常核验结果：`status` 为 `inconsistent`，三个数组为空、`plan` 为 `null`，不能据此推断任何池已确认。

## 输出

成功时原子新建一个 JSON 对象（不覆盖已有目标，含符号链接），包含 `status`、`pots`、`uncalled_returns`、`witnesses`、`plan`：

- `pots` 按 v1 池号列出，每项含 `pot, from_exclusive, to_inclusive, amount, status, awards`。某池在**每种**可行补全中的逐玩家整数分配映射完全相同才为 `certified` 并给出该映射；否则为 `ambiguous` 且 `awards` 为 `null`。即使其他池未确认，已确认的池照常交付。
- 所有池都已确认（包括没有匹配池但有可行补全）时，根 `status` 为 `certified`，否则为 `ambiguous`；无可行补全时为 `inconsistent`。
- `uncalled_returns` 沿用 v1 格式。
- 仅在根状态为 `ambiguous` 时给出两个 `witnesses`：每个 `source` 是遵守原证据的完整 v1 输入，`report` 是其完整 v1 报告，两份报告至少一个池的分配不同。凭据不会把只在不同世界才可能出现的牌拼在一起；其中的牌型与最强五张只说明该补全。
- 同一输入的报告稳定，不随机抽样，也不把所有补全逐条写进报告。

## 回看决策树 `plan`

`plan` 是保证把**全部**池分配确认下来的自适应指引，而不是某张牌恰好出现才奏效的建议：

- 已确认节点直接结束，叶子为 `{"awards": [{"pot": 1, "awards": {…}}, …]}`，按池号给出该节点已确定的全部池分配。
- 否则节点为 `{"slot_id": "…", "branches": {"6c": 子节点, …}}`：选择一个仍可回看的牌位，分支恰好覆盖在此前观测下仍有可行补全的牌；只在原候选表中存在、但已被其他明示牌占用的牌不会出现。
- 每条路径不重复回看同一牌位；叶子结果对符合整条路径观测的所有补全成立。
- 节点在能保证确认的牌位中选择最少的最坏情况回看次数；同成本时，选择最坏分支剩余可行补全最少、再选分支更细、最后按 `slot_id` 的 ASCII 顺序取最小者。
- 当前预算内没有保证成功的指引时，根 `plan` 为 `null`，不发布只覆盖部分观测的树；根上的逐池判断与所需见证仍照常交付。给出可行指引不改变根上的当前核验结论。

## 核验引擎

- 物理牌可行性用二分图匹配回答：每个未决牌位必须能匹配到一张尚未被固定牌或已观测牌占用的候选。弃牌者底牌中的候选牌位永不进入牌力、资格或退回计算，只参与该匹配。
- 当剩余相关牌位互不影响（公共牌无未决牌位、候选牌不被两个牌位或固定牌共享）时，按各存活玩家可达到的牌力集合做符号化判断，避免枚举玩家选择的笛卡尔积；耦合的子问题回退到记忆化枚举，并在每个池都已确认有歧义后提前终止。
- 每个补全都交给未改动的 v1 结算，见证中的 `source` 可直接作为 `showdown-pots` 的输入复算。

## 命令行

```sh
showdown-audit --source audit-request.json --output run/audit-report.json
```

成功时 stdout 打印如 `{"pots": 1, "status": "ambiguous"}` 的摘要并原子新建报告；输入或文件错误在 stderr 说明并以状态 2 退出，不生成结果。可执行回归测试见 `tests/test_audit.py`。

## 边界

仅支持单手、固定一副牌与最多 12 个候选牌位；没有下注街次合法性审查、抽水、保险、多次发牌或真实资金接入。输出是教学核验记录，不是赌场结算认证。
