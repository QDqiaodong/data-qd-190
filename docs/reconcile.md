# 双源对账 `showdown-reconcile`

`showdown-reconcile` 对同一张教学桌的两份独立导出做身份核对与筹码核对。牌谱端（`left`）保存可结算的完整 v1 单手输入，计分端（`right`）只记每手实际抄到的逐人净额。两端都可能漏手、桌边短码可能重复、设备时钟没有同步；本命令先确定哪些左右记录是同一手，再只对已确认配对给出筹码差异。它复用 v1 的牌力、边池、弃牌资格、退回与平局余数语义，不连接资金或游戏服务，也不读写跨手账本。旧命令 `showdown-pots`、`showdown-ledger`、`showdown-audit` 的输入、输出与错误行为不变。

## 输入

```json
{
  "left":  [{"id": "L0", "seq": 1, "ts": 90, "tag": "K", "hand": {"...": "v1 单手输入"}}],
  "right": [{"id": "R0", "seq": 1, "ts": 91, "tag": "K", "net": {"A": 4, "B": -5}}],
  "clock": {"min_offset": -86400000, "max_offset": 86400000, "tolerance": 1},
  "anchors": [{"left_id": "L1", "right_id": "R3"}],
  "focus_left_id": "L2"
}
```

- `left`、`right` 各 0..100 条。`id`、`tag` 沿用玩家 ID 字符规则 `[A-Za-z0-9_:-]{1,64}`，大小写敏感；`id` 只需在各自一侧唯一，两端 ID 相同没有匹配含义。
- `seq` 为 1..10^9 的整数，在同侧唯一、可跳号；它只确定同侧手序，命令不依赖输入数组顺序，也不要求时间戳单调。
- `ts` 为 0..10^12 的整数毫秒。`tag` 是双方共用的桌边短码，同侧可重复。
- `left[].hand` 是完整 v1 单手输入。每条左记录都会按 v1 规则验证并结算，**即使它最终没有配对**；无法结算的牌谱是输入错误。
- `right[].net` 是玩家 ID 到整数筹码净额的映射，0..9 个键，值在 −9×10^9..9×10^9。允许漏记、多记玩家或净额和不为零——这些正是待对账的事实。
- `clock.min_offset`、`max_offset` 为 −10^12..10^12 的整数且下界不大于上界，`tolerance` 为 0..10^6 的整数毫秒。
- `anchors` 为 0..100 项 `{left_id,right_id}`，两侧引用都必须存在、各自不能重复。每项是教务人工查证的同一手，本次对齐必须保留；它不是优先分，也不能借此对不同记录用不同钟差。
- 可选的 `focus_left_id` 必须指向左侧现存记录。

## 认定同一手

一个可行对齐 = 一个整数钟差 `offset`（在闭区间内，整批共用）+ 一组左右配对。每条记录至多用一次；按左侧 `seq` 升序排列配对时，右侧 `seq` 必须严格递增。每对短码相同，并满足 `abs((right.ts-left.ts)-offset) <= tolerance`。所有锚点必须同时出现。不会从牌力、筹码、净额相似度、记录 ID 相同或时间更近推断额外匹配条件。

只在可行对齐中求最大配对数；所有达到最大值的对齐同等有效，不选代表解。`offsets` 因此给出**恰能达到最大配对数的全部整数钟差**，按下界升序，相邻整数区间合并，但保留中间空洞。钟差扫描只访问候选边给出的边界 `right.ts-left.ts ± tolerance`，不会逐毫秒遍历先验窗宽。

## 输出

成功时原子新建一个 JSON 对象（不覆盖已有目标，含符号链接）：

- 可行时 `status="ok"`、`max_pairs` 为最大配对数、`offsets` 为 `{from,to}` 闭区间数组。
- `left`、`right` 列出该侧所有记录，各项 `{id,partners,may_be_unmatched}`。`partners` 是在至少一个最大对齐中与它匹配的对侧记录 ID；`may_be_unmatched` 表示至少一个最大对齐不使用本条。清单与伙伴各按所属侧 `seq` 排序。
- 没有任何可配边且无锚点时仍为 `ok`：最大数为 0、钟差为整个输入区间、双方均无伙伴且可不配。
- `reconciled` 只含**已确认配对**：某左记录有且只有一个可能伙伴，且任何最大对齐都不能不配它。按左侧 `seq` 排序，各项 `{left_id,right_id,differences}`。差异用 v1 完整结算的逐人 `net` 为应记值，保留边池、弃牌、退回和平局余数语义；列表依玩家 ID 的 ASCII 顺序给 `{player_id,expected,observed}`，只列不相等项，缺键为 `null`（与 0 不同），一致项差异为 `[]`。
- 未确认配对绝不出筹码差异，哪怕它只剩一个可能伙伴，或某套对齐能让更多金额相符。
- `focus_left_id` 的关注记录若在最大对齐中有两种或以上去向（配到不同右 ID，或不配），`examples` 给两条完整见证 `{offset,pairs}`；`pairs` 按左 `seq` 升序。两条都达到全批最大配对数，且在关注记录的去向上不同。任取合法见证，但重排输入数组不改变报告。未指定关注记录或去向唯一时 `examples=[]`。
- 引用合法但锚点无法共同满足手序、短码或公共钟差时，这是业务结果：`status="no_alignment"`、`max_pairs=null`，其余五个数组全空；不会丢掉冲突锚点改报成功。

字段、类型、范围、重复身份、悬空引用、重复锚点端或不能按 v1 结算的牌谱是输入错误：stderr 说明原因、退出 2，不发布部分结果。

## 命令行

```sh
showdown-reconcile --source request.json --output run/reconcile-report.json
```

成功时 stdout 打印如 `{"max_pairs": 4, "reconciled": 1, "status": "ok"}` 的摘要并原子新建报告；输入或文件错误在 stderr 说明并以状态 2 退出。离线回归测试见 `tests/test_reconcile.py`。

## 边界

一次处理同一张桌的一个导出批次，不维护历史状态，不跨批次借用锚点或钟差。仅支持单手 v1 牌谱；没有下注街次合法性审查、抽水或真实资金接入。输出是教学对账记录，不是赌场结算认证。
